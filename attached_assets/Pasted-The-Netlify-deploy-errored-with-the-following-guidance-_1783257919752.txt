Diagnosis
- Vite / Rollup could not resolve the module "@radix-ui/react-accordion" that is imported from your client UI component (see the error at [line 64](#L64)). This means the bundler did not find that package (or file) in the installed node_modules or the import path is incorrect.
- Most likely causes:
  - The package is not declared or installed in the repo's package.json (or it’s declared in a subpackage that wasn’t installed by the root install).
  - The package is declared but not available to the build (monorepo/workspace subpackage not installed, or declared only in devDependencies when it’s required for the production build).
- Do NOT immediately externalize the package in Rollup unless you intentionally want the dependency to be excluded from the client bundle — first verify the package is present/installed as described below.

Solution (step-by-step)
1. Verify the package declaration
   - Check the root package.json and the client package.json in your repo to see where dependencies live:
     - Root package.json: https://github.com/skelleyboy/susienew/blob/main/package.json
     - Client package.json (likely): https://github.com/skelleyboy/susienew/blob/main/client/package.json
   - Confirm "@radix-ui/react-accordion" appears in dependencies (not only devDependencies) in whichever package.json you expect the client build to use.

2. If the package is missing, add and commit it
   - From project root (or inside client if it is a subproject):
```bash
# in project root or client folder as appropriate
npm install @radix-ui/react-accordion
git add package.json package-lock.json
git commit -m "chore: add @radix-ui/react-accordion dependency"
git push
```
   - Re-deploy on Netlify.

3. If the package is declared in client/package.json but Netlify didn’t install it
   - Your logs show "No npm workspaces detected" — if the client is a subproject but you are not using workspaces, Netlify's root install may not have installed client dependencies.
   - Option A — install client deps during the build: update your Netlify build.command to first install client deps, then build. Example in netlify.toml OR Netlify UI:
```toml
# Example netlify.toml snippet (adjust to your project)
[build]
  command = "cd client && npm ci && npm run build && cd .. && npm run other-root-build-if-needed"
  publish = "dist/public"
```
   - Option B — make the client package part of root workspaces and ensure workspaces are detected (add "workspaces" in root package.json) so Netlify installs all workspace packages. If you choose this, ensure root package.json lists the workspaces properly and push that change.

4. If the package is present and installed but Vite still fails
   - Ensure the import path in the component is correct. The component referenced by the error is in the repo at:
     - client source (likely): https://github.com/skelleyboy/susienew/blob/main/client/src/components/ui/accordion.tsx
   - If you intentionally want Rollup to treat the package as external (rare for UI libraries used in client bundles), first verify the package is in package.json (see step 1). If you still want externalization, add this to your vite.config.ts:
```ts
// vite.config.ts
export default defineConfig({
  // ...
  build: {
    rollupOptions: {
      external: ['@radix-ui/react-accordion']
    }
  }
});
```
   - Note: externalizing will exclude it from the bundle and assume it will be provided at runtime — do this only if you know the package should not be bundled.

5. Redeploy
   - After making the fixes and pushing, trigger a new Netlify deploy. The Vite build should now resolve the import and complete.
