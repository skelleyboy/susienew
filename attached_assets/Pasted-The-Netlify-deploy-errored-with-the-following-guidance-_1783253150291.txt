The failing imports are coming from files under client/ (example list in the log, e.g. [line 173](#L173) and nearby), which suggests the client/ package dependencies were not available to Vite when building.
- Likely cause: the @radix-ui package (or other client dependencies) are not installed in the location where Vite is building (client code running under the root build), so Rollup cannot resolve the module.

Solution
1) Verify the dependency is declared
- Open the client package.json and confirm @radix-ui/react-accordion is listed in dependencies:
  https://github.com/skelleyboy/susienew/blob/main/client/package.json
- If it is missing, add it to client/package.json (or to the root package.json if you intend to install dependencies at root).

If the dependency is missing, install it (example commands):
- From the client folder:
```bash
cd client
npm install @radix-ui/react-accordion
```
- Or from the repo root (installs into client node_modules):
```bash
npm --prefix client install @radix-ui/react-accordion
```

2) Ensure Netlify installs the client deps before building
- Because Netlify detected "No npm workspaces", the client/ folder dependencies are not automatically installed. Modify your Netlify build command so client dependencies are installed prior to running the build. Update your netlify.toml build.command (or the Build settings) to something like:
```bash
# Example: install client deps and run build from client
npm --prefix client ci && npm --prefix client run build
```
or
```bash
# If your root build script starts a custom script that builds client, ensure it installs client deps first:
cd client && npm ci && npm run build
```
Make sure you commit the updated netlify.toml (or change the Build command in the Netlify UI).

3) (Only if package is present and the module still fails to resolve)
- Verify node_modules is present under client/ after your install step in the Netlify build logs.
- As a last resort you can externalize the module in Vite’s rollup options, but only after you confirm the package exists in package.json and is committed. To externalize (not usually recommended for this case), add to vite.config.ts:
```ts
// vite.config.ts
export default defineConfig({
  // ...
  build: {
    rollupOptions: {
      external: ['@radix-ui/react-accordion']
    }
  }
});
```
(Only do this if you understand the package will then be expected to be provided at runtime externally.)
