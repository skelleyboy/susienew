Diagnosis
- npm cannot reach a private/internal registry (package-firewall.replit.local) during install, causing the build to fail with ENOTFOUND. This usually happens because a project-level or environment npm config (.npmrc or NPM_CONFIG_REGISTRY) points to a non-public registry, or the lockfile contains resolved URLs pointing to that registry.

Solution — steps to fix and verify
1. Verify what registry is configured in the repo
   - Search the repo for any npm config that points to the Replit firewall:
     - git grep -n "package-firewall" || true
     - git grep -n "registry=" || true
   - Check these files in the repo (if present): .npmrc, package.json, package-lock.json / npm-shrinkwrap.json.
     - package.json: https://github.com/skelleyboy/susienew/blob/main/package.json
     - package-lock.json: https://github.com/skelleyboy/susienew/blob/main/package-lock.json
2. If you find a .npmrc (or other config) that points to the Replit registry, change it to the public npm registry (or remove the file), commit, and push:
   - Example .npmrc to use the public registry:
```text
registry=https://registry.npmjs.org/
```
   - Commit the change and push. Then trigger a new Netlify build.
3. If package-lock.json contains resolved URLs that reference the internal registry, regenerate the lockfile locally after updating .npmrc:
   - Locally:
     - rm -rf node_modules
     - npm cache clean --force
     - npm install    # regenerates lockfile entries with the correct registry
   - Commit the updated package-lock.json and push.
4. If you intentionally need a private registry (private packages):
   - Verify the private package is listed in package.json and is accessible from Netlify.
   - Add the appropriate auth token as a Netlify build environment variable (for npm using NPM_TOKEN) and configure .npmrc to use it:
```text
//registry.npmjs.org/:_authToken=${NPM_TOKEN}
```
   - In Netlify UI: Site settings → Build & deploy → Environment → Add variable NPM_TOKEN with the token value.
5. As an alternative if you cannot change repo files, set the registry at build time in Netlify (Site settings → Build & deploy → Environment):
   - Add NPM_CONFIG_REGISTRY = https://registry.npmjs.org/
   - That will force npm to use the public registry for the build.
6. Re-run the build on Netlify. The install step should now contact the public registry and succeed.

Notes
- The failure is network/config related (registry URL), not a Vite or Node compatibility issue. If at any point you suspect Node version problems, Netlify docs for changing Node versions are here: https://docs.netlify.com/configure-builds/manage-dependencies/#node-js-and-javascript.
