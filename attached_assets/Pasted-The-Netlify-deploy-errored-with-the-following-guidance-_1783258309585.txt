The Netlify deploy errored, with the following guidance provided:

- Relevant log lines
  - [line 21](#L21) shows an npm internal error during install.
  - The failing error is the npm ENOTEMPTY rename failure: [line 58](#L58) through [line 64](#L64).

- Diagnosis
  - Error type: npm install failure (ENOTEMPTY, errno -39) while renaming a scoped package directory.
  - Root cause: npm attempted to rename /node_modules/@radix-ui/react-accordion to a temporary name during install but the destination already existed and was not empty, causing the rename to fail. This commonly happens because of leftover node_modules state (partial/previous installs, build cache) or an npm race/rename edge-case when doing installs on top of an existing node_modules tree.

- Solution
  1. Change the build command to perform a clean, deterministic install. In your netlify.toml replace the current build.command ("npm install && npm run build") with an npm ci flow that removes node_modules and installs from the lockfile:
     - Edit /netlify.toml (repo file: https://github.com/skelleyboy/susienew/blob/main/netlify.toml) and update the command. Example change:
     ```toml
     [build]
     command = "npm ci && npm run build"
     publish = "dist/public"
     ```
     (If you prefer to keep the command inline in your Netlify UI, replace it there instead.)

  2. Clear Netlify’s build cache and re-deploy once the command is updated. The cached node_modules can cause the same rename conflict; from the Netlify UI choose "Clear cache and deploy site", or trigger a deploy after the change with the checkbox to clear cache.

  3. If you still see the error after the above:
     - Try removing any committed node_modules (should not be committed) and ensure package-lock.json is present and consistent with package.json.
     - As an alternative to the CI change, you can force a clean install in the build step:
       ```bash
       rm -rf node_modules && npm ci && npm run build
       ```
     - If the install continues to fail intermittently, try upgrading/downgrading npm (rare) or pinning a different npm version. If you change Node/npm settings, see Netlify docs for changing Node versions: https://docs.netlify.com/configure-builds/manage-dependencies/#node-js-and-javascript

Notes:
- Using npm ci ensures node_modules is removed and a clean install happens from package-lock.json, which prevents the rename/leftover-dir race that produced ENOTEMPTY. Clearing the cache ensures no stale node_modules persist between builds.
